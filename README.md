## Описание
"Дневник читателя" — сайт, где читатель ведёт учёт своих книг и делится впечатлениями.

- **Дневник** (главная страница) — книги по колонкам «Читаю сейчас», «Хочу прочитать»,
  «Прочитано», «Брошено». Статус меняется кнопками, даты начала и конца чтения ставятся сами
  и правятся вручную. Одну книгу можно перечитывать — ранние прочтения видны в её истории.
  Книгу, которой нет в каталоге, можно быстро завести прямо из дневника черновиком.
- **Каталог** (`/books/`) — общий для всех: поиск, фильтры по жанру и автору, средняя оценка
  и число прочтений, пометка «в моём дневнике». Книги добавляют и дозаполняют сами читатели.
- **Отзывы** с оценкой 1–5 на странице книги; свои отзывы можно править и удалять.
- **Страница читателя** — его дневник целиком (дневник публичный).
- **Ничего не удаляется физически**: удалённое помечается и может быть восстановлено админом.
  Удаление книги скрывает и связанные с ней записи дневника и отзывы.
- **Журнал событий** по книгам и авторам (кто, когда, что изменил) — в админке, пишется
  фоновой задачей Celery.

Вход — по email. Пользователей удаляет только админ.


## Установка зависимостей (poetry)
```shell
# Для Ubuntu
pip install poetry

# Для Debian 13
curl -sSL https://install.python-poetry.org | python3 -
poetry config virtualenvs.in-project true

# Зависимости
poetry install

# Загрузка окружения
source .venv/bin/activate
```


## Настройки
База — PostgreSQL, параметры подключения берутся из файла `.env` в корне проекта:
```shell
cp .env.example .env    # и вписать свои POSTGRES_USER / PASSWORD / DB / HOST / PORT
```
Без запущенной базы не работают ни сайт, ни тесты. Для локального запуска
её проще всего поднять из докера (`POSTGRES_HOST=localhost`):
```shell
docker compose up -d db
```

## Демо данные
Для предварительного наполнения базы есть демонстрационные данные на русском: настоящие книги
и авторы с описаниями, вымышленные читатели (пароль у всех `12345`), их дневники и отзывы.
Повторный запуск ничего не дублирует; `--seed N` делает дневники и отзывы воспроизводимыми.
```shell
# Жанры, авторы, книги, читатели, дневники и отзывы
python manage.py gen_data

# Создать пользователя Админа для /admin
python manage.py createsuperuser

# Очистить базу (все записи, включая админа; схема остаётся)
make clean

# Очистить и заново наполнить демо-данными
make reset
```


## Запуск в докере (всё сразу)
Приложению нужны четыре процесса: PostgreSQL, Redis (брокер), веб-сервер и celery-воркер.
`docker compose` поднимает их вместе:
```shell
docker compose up --build      # первый запуск
docker compose up -d           # дальше — в фоне
```
Сайт — http://localhost:8000/, миграции применяются автоматически при старте.

```shell
docker compose ps              # состояние сервисов
docker compose logs -f worker  # сообщения фоновых задач
docker compose down            # остановить всё
```

База и очередь Redis хранятся в томах докера и переживают `docker compose down`
(`docker compose down -v` удалит их вместе с данными). Папка проекта примонтирована
в контейнеры, поэтому `media/` остаётся на хосте, а правки кода подхватываются
автоперезагрузкой runserver. Management-команды выполняются в контейнере:
```shell
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py gen_data
```

Если uid на хосте не 1000, его надо передать при сборке, иначе созданные
в контейнере файлы будут чужими:
```shell
APP_UID=$(id -u) APP_GID=$(id -g) docker compose build
```


## Запуск без докера
Сервер и воркер запускаются в отдельных терминалах, Redis и база — из докера:
```shell
docker compose up -d redis db        # брокер и база

python manage.py runserver           # первый терминал
celery -A config worker -l info      # второй терминал
```


## Тесты и линтер
```shell
make test        # тесты
make coverage    # тесты с покрытием, ниже 95% — ошибка
make lint        # pylint
```
Задачи Celery в тестах выполняются синхронно (`CELERY_TASK_ALWAYS_EAGER`),
поэтому запущенный Redis для тестов не нужен, а база — нужна.
Те же `make lint` и `make coverage` запускают CI на GitHub, GitLab и GitVerse.

# План работ: превратить каталог в дневник читателя

> Проект ещё не развёрнут, боевых данных нет: миграции можно пересобрать с нуля,
> модели менять свободно, `db.sqlite3` и `fixtures/bookshelf_export.json` — выбросить.
> На этапы домашних заданий больше не оглядываемся: они зафиксированы тегами `stage-1`…`stage-6`,
> дальше проект развивается как обычный сайт, а не как цепочка ДЗ.

## Что уже есть

- `bookshelf_app`: `Author`, `Genre`, `Book` (+`added_by`), `Review` (оценка 1–5, пишутся и
  правятся на странице книги), CRUD книг на CBV, примесь `Breadcrumbs`, общий каталог `/books/`
  со средней оценкой и числом прочтений.
- `user_app`: `CustomUser` (вход по email), регистрация/вход/профиль, публичная страница читателя.
- Инфраструктура: Postgres, Celery + Redis (`log_event_task` пишет журнал событий), тесты
  (порог покрытия 95%), три CI, docker compose.
- Журнал событий по книгам и авторам (`EventLog`) с просмотром в админке.
- Главная страница — дневник читателя по колонкам статусов (гостю — приветствие); статусы
  меняются кнопками, записи правятся и удаляются, книгу можно быстро завести из дневника.
- Каталог с поиском, фильтрами по жанру и автору, пагинацией и пометкой «в моём дневнике».

## Чего не хватает главного

Тестов и документации под итоговую модель (этап 8).

## Принятые решения (детали — в `TODO.md`)

- Дневник живёт в `bookshelf_app`, отдельное приложение не заводим.
- Статусы: «хочу прочитать» / «читаю» / «прочитано» / «брошено».
- Ведём **историю прочтений**: одну книгу можно читать несколько раз, записей на пару
  «читатель + книга» может быть много.
- Отзыв — отдельная сущность с собственной оценкой, привязан к книге, а не к прочтению;
  своих отзывов на книгу может быть несколько, их можно править и удалять.
- Даты начала и конца проставляются автоматически при смене статуса, но правятся руками.
- Дневник публичный: на странице читателя показываем его целиком.
- **Ничего не удаляется физически.** Удаление пользователем — пометка «удалено» в базе,
  админ может восстановить. Пользователя удаляет только админ; это не удаляет его книги — сам он
  больше не может войти, но его книги, записи дневника и отзывы остаются видимыми.
- Автора с неудалёнными книгами удалить нельзя: сначала книги, потом автор.
- Книгу вправе удалить добавивший её читатель или админ; чужие записи дневника на эту книгу
  помечаются удалёнными вместе с ней.
- Журнал событий ведём только по `Book` и `Author` (создание, изменение, удаление,
  восстановление), со старыми и новыми значениями полей, и не чистим.
- Заметок, цитат и прогресса чтения не будет — для учебного проекта лишнее.

## Этапы

### 1. Модели дневника ✅ сделано
- `ReadingEntry` в `bookshelf_app/models.py`: FK `reader`, FK `book`,
  `status` (`planned` / `reading` / `read` / `abandoned`, `TextChoices`),
  `started_at`, `finished_at` (обе редактируемые), `created_at`, `updated_at`.
  Ограничения уникальности нет — это история прочтений; в дневнике показываем последнюю запись.
- `Review` остаётся отдельной моделью: FK на книгу, FK на читателя, `rating` (1–5) у каждого
  отзыва, `text`, `created_at`. Отзывов на книгу может быть несколько, свои можно править
  и удалять; к конкретному прочтению отзыв не привязан.
- `Book.is_pending` — флаг «требует дозаполнения» для книг из быстрой формы.
- Миграции удалить и сгенерировать заново (`0001_initial`), БД пересоздать.
- Админка и `gen_data` — под новые модели.

### 2. Мягкое удаление (сквозная подсистема) ✅ сделано
- Абстрактная `SoftDeleteModel` в `bookshelf_app/soft_delete.py`: `is_deleted`, `deleted_at`,
  `deleted_by`; `delete(user=...)` модели и выборки только ставит пометку, `restore()` снимает.
- Два менеджера: `objects` (только живые, он же менеджер по умолчанию) и `all_objects` (всё) —
  сайт видит первый, админка второй. Прямые FK (`review.book`, `book.added_by`) видят и удалённых.
- Наследуют её `Book`, `Author`, `ReadingEntry`, `Review`, `CustomUser`. Связи модель описывает
  сама: `soft_delete_cascade` (что удаляется и восстанавливается вместе с объектом) и
  `soft_delete_protect` (что мешает удалению, аналог PROTECT).
- `Book.added_by`: `on_delete=SET_NULL`, поле nullable — в шаблонах «Добавил: неизвестно».
- Удаление книги помечает её отзывы и записи дневника всех читателей; восстановление книги
  возвращает только то, что было удалено вместе с ней. Автора с живыми книгами удалить нельзя —
  сначала удаляются книги, потом автор.
  В окне подтверждения — сколько записей дневника и отзывов будет затронуто. Удалить книгу
  может добавивший её читатель или админ (`is_staff`), остальным — 403 и кнопки нет.
- Мягко удалённый пользователь не проходит аутентификацию и теряет открытые сессии
  (`ModelBackend` ищет через менеджер по умолчанию). Его книги, записи и отзывы остаются на сайте,
  страница читателя — тоже, с пометкой «Учётная запись удалена». Email остаётся занятым,
  сообщение при регистрации стандартное.
- В админке (`SoftDeleteAdmin`) — колонка и фильтр «Удалено», действие «Восстановить выбранные»,
  штатное удаление тоже мягкое, а страница подтверждения перечисляет реальный каскад.
- Удалить пользователя может только админ — страницы «удалить свою учётную запись» на сайте нет.

### 3. Главная страница = дневник ✅ сделано
- `IndexView`: гостю — приветствие, кнопки регистрации/входа и ссылка на каталог; читателю —
  колонки «Читаю сейчас», «Хочу прочитать», «Прочитано», «Брошено» по его записям.
- Раскладка — `bookshelf_app/diary.py::build_diary()`: книга попадает в колонку по статусу
  своей последней записи, более ранние записи — её «История прочтений (N)» на карточке.
  Удалённые записи и записи об удалённых книгах не показываются.
- Счётчики в заголовках колонок и общий «Книг в дневнике», ссылки на карточку книги, даты
  прочтения; пустой дневник — подсказка со ссылкой на каталог.

### 4. Работа с дневником ✅ сделано
- Кнопки смены статуса (`include/status_buttons.html`, POST на `/books/<pk>/status/`) — на странице
  книги, в каталоге, в своём дневнике и в результатах поиска. Переходы — `diary.py::TRANSITIONS`:
  нет в дневнике → «Хочу прочитать» / «Читаю» / «Прочитано»; «Хочу прочитать» → «Читаю» /
  «Прочитано»; «Читаю» → «Прочитано» / «Бросил»; после «Прочитано» и «Брошено» — «Хочу прочитать» /
  «Перечитать», и это уже новая запись (история прочтений). Даты ставит `apply_status()`.
- Форма записи `/diary/entries/<pk>/edit/`: статус и даты руками; оттуда же — мягкое удаление
  записи (`/diary/entries/<pk>/delete/`). Чужие записи и записи удалённых книг — 404.
- Дневник на странице читателя и в профиле — те же колонки (`include/diary_columns.html`);
  кнопки и правка — только на своей странице.
- Быстрое добавление `/diary/add/?q=…`: поиск по названию, под результатами — «Такой книги нет
  в базе, добавить?» и короткая форма (название, автор строкой, статус). Автор ищется без учёта
  регистра или заводится новый, книга получает `is_pending=True` и бейдж «черновик».
  Дозаполнение полной формой снимает флаг; в админке — фильтр и действие «подтвердить».

### 5. Отзывы через сайт ✅ сделано
- `ReviewForm` (оценка списком 5…1 звёзд + текст). Новый отзыв — `/books/<pk>/reviews/add/`
  (кнопка «Написать отзыв» на странице книги, отзывов может быть несколько); правка и мягкое
  удаление своих — `/reviews/<pk>/edit|delete/`, ссылки только у своих отзывов, чужие — 404.
- Перевод книги кнопкой в «Прочитано» — в сообщении ссылка «Написать отзыв?» (только для кнопки,
  не для быстрого добавления и формы записи).
- `views.with_book_stats()` — `avg_rating` (среднее по живым отзывам) и `readings_count`
  (живые записи «Прочитано»: перечитывание — отдельное прочтение, брошенные не в счёт)
  подзапросами; показываются в каталоге и на странице книги (`include/book_stats.html`),
  там же — все отзывы.

### 6. Журнал событий ✅ сделано
- `EventLog` (`bookshelf_app/models.py`): `user` (кто, `SET_NULL`), `action` (создание / изменение /
  удаление / восстановление), `object_type` (`book` / `author`) + `object_id` + `object_repr`
  (название на момент события, без FK), `created_at`, `changes` — JSON
  `{поле: {"old": …, "new": …}}`. Для создания — все заполненные поля, для изменения — только
  изменившиеся (жанры списком, связи и даты строками); сохранили без изменений — события нет.
  Сравниваются все поля, включая `added_by` и `is_pending`: снятие флага черновика — это изменение.
- `bookshelf_app/events.py`: `log_created/updated/deleted/restored()` вызываются явно там, где
  известен пользователь: вьюхи книг, быстрое добавление (книга и новый автор), админка книг и
  авторов (`EventLogMixin`: сохранение, удаление, «Восстановить», «Подтвердить»). Задачу
  `tasks.log_event_task` ставят через `transaction.on_commit()`, время события фиксируется до очереди.
  Заменила `log_new_book_task`. Дневник, отзывы, пользователи и `gen_data` в журнал не пишутся.
- Админка «Журнал событий»: только чтение (нет добавления, правки, удаления), фильтры по
  пользователю (включая удалённых), типу объекта, действию и дате, `date_hierarchy`, ссылка на
  объект, изменения таблицей «Поле — Было — Стало». Журнал не чистим.

### 7. Каталог как второстепенная вкладка ✅ сделано
- `BookFilterForm` (GET): универсальный поиск без учёта регистра — каждое слово запроса должно
  найтись в названии, имени автора, описании или жанре; фильтры по жанру и автору. Неверное
  значение — не ошибка, а пропущенный фильтр. Книги по названию, по `CATALOG_PAGE_SIZE` (12) на страницу,
  ссылки пагинации (`include/pagination.html`) сохраняют фильтры, счётчик «Всего» — по всем страницам.
- Читателю у книги со статусом — бейдж «В моём дневнике: <статус>» (статус последней записи).
- Меню: «Мой дневник» (главная; гостю — «Главная»), «Все книги», «Добавить книгу», «О сайте».
